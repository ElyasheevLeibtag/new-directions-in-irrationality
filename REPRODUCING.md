# Reproducing the supplement

## Environment

The release was tested with Python 3.12.14 and the versions pinned in
`python/requirements.txt`. The root `requirements.txt` includes that file.
Create a virtual environment and install those requirements as shown in the
README. The runner records the actual versions in its execution report.
The full tested package inventory is in `verification/environment.txt`;
it is a provenance record, not a universal cross-platform lockfile.

## Commands from the package root

```sh
python verify_release.py
python run_all.py --section6-only
python run_all.py --additional-only
```

`python run_all.py` runs both components. Each additional script starts in
a separate process; every notebook starts in a separate Jupyter kernel.
`--timeout 1800` controls the timeout per job. The notebook runner also has
its own per-cell timeout. This is CPU computation; no GPU or Lean
installation is required.

To open and execute one notebook interactively, use a notebook editor with
the installed environment and choose Restart Kernel and Run All. Alternatively:

```sh
python python/run_notebooks.py pure_zeta3/02_pure_zeta3_divisor_and_measure.ipynb
```

## Results and verification

- Root-level orchestration logs and reports go to `verification/`.
- Notebook execution reports and executed copies go to `python/verification/`.
- The joint density, cells and bounds are regenerated in `python/joint/results/`.
- The ζ(2) notebooks regenerate their JSON certificates and `generated/` logs.
- Additional checks regenerate adjacent JSON files, where applicable.

Check the process exit status and report status, not just printed decimal
values. Scripts using assertions must be run without optimization. The
entry points explicitly refuse optimization. A successful finite diagnostic
is not an all-index proof. In particular the convergence, uniform prime
divisibility, prime number theorem and irrationality-measure criterion remain
the mathematical inputs explained in the paper and notebook text.

The source/data manifest excludes regenerable results, logs and runtime
state, so it remains useful after execution. `MANIFEST.sha256` is a snapshot
of the delivered files; regenerating outputs may change that snapshot.
Input archive hashes identify the received sources. Neither checksum proves
a mathematical theorem.

## Portability

All computation paths resolve within the extracted package. No original
download, other project directory, private repository or saved notebook
session is required. Installation may download public dependencies.
Notebook execution needs local Jupyter kernel communication; restrictive
sandboxes may block it even when the computations themselves are valid.

The manuscript has not been compiled as part of this computational check.
Its source snapshot includes the referenced figure exports, bibliography and
preamble. Raw plotting data and plotting notebooks were not present in the
two received archives; those figures are not regenerated by these commands.

## Lean source projects

Lean is separate from `run_all.py`. See [the Lean guide](lean/README.md)
for all three projects, exact pins and assumption statements. Use
`python lean/check_projects.py --plan` to inspect the build commands and
`python lean/check_projects.py` to execute them. These commands require
Lean/elan and public dependency downloads, unlike the Python-only run above.
The included source has not been independently compiled for this release.
